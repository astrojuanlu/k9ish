## What we have learned
- **GITHUB_TOKEN can never push `.github/workflows/*` changes** — no `workflows` scope exists in its `permissions` block (actionlint rejects the key; live run confirmed). Only a PAT with `workflow` scope can — hence `SYNC_TOKEN`, verified working.
- GraphQL `createPullRequest` (`gh pr create`) is denied to GITHUB_TOKEN when head history isn't a descendant of base; REST `POST /repos/{o}/{r}/pulls` works; user-token `gh pr create` also works.
- **`gh pr view <branch>` matches CLOSED PRs too** — guard on `gh pr list --state open`. This caused the current bug: user "deleted" #9 (it exists as CLOSED) and the green run edited it instead of creating a new PR.
- Idempotency: open PR + unchanged upstream → no-op; upstream moved → same PR updated (force-push discards in-PR conflict resolutions — resolve promptly); merged → count 0; runs serialized by concurrency group.
